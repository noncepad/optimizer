Pass 2 — key steps

One numbered path per box: what actually runs, in order, verified against source. Arb-relevant boxes get the full sequence; everything else gets the short version.

catscope-rust-bot — WASM guest

event_loop.rs

the poll loop every module above runs inside

  1. on_load() builds the account-subscription Graph, registers callbacks, flushes any startup messages
  2. loop: general::ready() blocks for the next WIT wake-up — either stdin or a registered event id
  3. stdin data → queued as Event::Stdin; an event id → runs its callback, which queues the real typed event
  4. drains the queue into handler.on_event(), one call per event, then handler.flush()

arbv1 — cross-DEX price arbitrage

the real price-arb strategy

  1. on_load: subscribe to Orca Whirlpool + Sanctum S Controller pools, register mints, build the TradeRouter price graph
  2. every event updates pool/account state — LowLatency (~400ms, processed), Commit (~12s, rooted), Transaction, SlotStatus, Stdin (wallet key + ALT from Go)
  3. on each Commit: planner::find_opportunity() — cheap probe cycle first, then a real-size re-search at actual wallet balance (slippage-aware), kept only if profitable
  4. evaluate() runs after every event: warm-up gate (slot_delta ≥ 20 and tx_count ≤ 10), then build_execution_plan()
  5. build_execution_plan(): for each hop, dex.execute_hop() builds the swap instruction into a scratch wallet; nets the profit in lamports if the start token is SOL
  6. wallet.assemble() drains the built tx(es) → sends via transactionprocessor::send(), tracks the signature, flips buy/sell direction
TODAYMIN_PROFIT_BPS = 0 — any non-negative cycle currently passes; there's no real profitability floor yet.

perpfundingv1 — funding-rate arbitrage

the real funding strategy

  1. every epoch: observe_phoenix() / observe_velocity() record each venue's annualized funding rate per shared symbol
  2. close_epoch() — hourly, matching both venues' real on-chain funding_period — builds a FundingEdge for every symbol both venues reported: long the cheap venue, short the expensive one
  3. pushes a new GraphLayer, evicts the oldest once over max_layers
  4. execute_spot_leg can sign a real transaction with the child key — nothing calls it automatically yet

testperpv1 — real-tx smoke test

not a strategy — proves the pipeline

  1. literal copy of perpfundingv1's module shape (same EventHandler, same event flow)
  2. evaluate() swapped out: bootstrap a Solend obligation, deposit a small amount of USDC, withdraw it
  3. repeat the same deposit/withdraw check against Kamino
  4. closes the one real gap this session found: earlier Python/solders scripts verified instruction shapes on mainnet directly, but never exercised the compiled WASM's own wallet-batching + signing path

trader/ — the quant engine

shared by arbv1 and perpfundingv1, not a strategy itself

pricegraph.rs
  1. PriceGraph: fair prices via Bellman-Ford on −ln(rate) edges
  2. TradeRouter.find_arbitrage(): same DAG, SPFA negative-cycle search
  3. find_arbitrage_slippage_aware(): re-searches with real cp_quote-composed amounts
spfa.rs
  1. SIMD 2-lane relaxation loop (WASM v128) per SPFA queue pop
  2. Small-Label-First queue ordering keeps convergence fast
  3. detect_negative_cycle_excluding() reruns minus a found cycle's edges, to surface distinct candidates
planner.rs
  1. find_opportunity(): probe at PROBE_AMOUNT_RAW (1,000,000) to pick a start token
  2. re-search at real balance, capped at REAL_SIZE_MAX_HOPS (4) hops
  3. reverify_with_exact_quotes(): re-checks Orca CLMM hops against exact tick-aware quotes — catches false positives the constant-product approximation misses
perp_router.rs
  1. time-layered directed multigraph — nodes are venues (Phoenix, Velocity/Drift)
  2. edges are per-asset FundingEdge spreads between venues
  3. layers are hourly snapshots, retained as a sequence — not overwritten

wallet.rs · tx.rs

signing and submission

  1. holds the child keypair; execute_hop / execute_spot_leg write instructions into it
  2. assemble() drains whatever got built; tx.rs submits and tracks signature/slot

optimizer — Go host

prefetch/* → prefetch.db

cmd download-arb

  1. dial the Solpipe bidder daemon to reach the validator
  2. per-protocol fetchers (orca, raydium amm/clmm/cpmm, sanctum, kamino, marginfi, solend, drift, pumpfun, pumpswap, phoenix) pull pool/reserve accounts over gRPC
  3. write into one unified prefetch.db — the same file build.rs reads at compile time and cmd/dashboard.go reads live

arbv1 — Go orchestrator

allocate → upload → handshake → wallet

  1. Init(): bidmgr.Allocate(bid=0) on a target pipeline — the free, non-voting Catscope validator
  2. build or download the WASM image with MODE=arbv1, upload — retries every 30s, 5 minute timeout
  3. wait for handshake, start the loopInstance goroutine
  4. initWallet(): derive the child key (index 1), subscribe its pubkey on the account graph, register both keys with the tx builder, send the wallet key to the bot over stdin
  5. Evaluate() fires on every solpipe/bidder state update: drains latency reports to a file, reads parent/child SOL balances

perpfundingv1 / testperpv1 — Go orchestrators

same pipeline as arbv1 above, two differences

  1. same Init() → build/upload → handshake → initWallet() sequence, just MODE=perpfundingv1 / MODE=testperpv1
  2. perpfundingv1's Evaluate() is a literal no-op — observation only, nothing to fund yet
  3. testperpv1 additionally hands over the real wallet key, since its Rust side signs real deposit/withdraw transactions

portfolio/

one implementation, two consumers

  1. reads portfolio.db, written separately by watch-balances
  2. same Positions/Bots calls used by cmd/pnl.go (renders HTML) and shell/tools.go (renders text for the LLM agent)

cmd/* and shell/*

the two ways to look at prefetch.db / portfolio.db

  1. cmd/dashboard.go: re-runs the summary queries against prefetch.db on every page load — read-only, no chain access
  2. shell/session.go: telnet listener spins up one goroutine per connection
  3. shell/chat.go: builds an eino react-agent over a local Ollama model; shell/tools.go exposes read-only queries (pnl, etc.) as agent tools
